# Ontology change types

OntoDiff currently compares only **OWL axioms**, not RDF triples yet. Let `R` be the axioms found only in the original ontology and `A` the axioms found only in the updated ontology. A candidate change has **removed evidence** from `R` and **added evidence** from `A`. Applying a candidate consumes that evidence, so another selected candidate cannot explain the same axiom.

An **atomic** change consumes one OWL axiom ( e.g. addition or removal). A **compound** change consumes two or more axioms. This counts evidence, not the number of meaningful operations: `NodeMove` is one operation explained by two axiom changes. A single OWL axiom, especially one containing a restriction, may be represented by several RDF triples and blank nodes.

In the table, `C`, `P`, and `Q` are named classes, and `S` is an IRI subject. For `EdgeCreation` and `EdgeDeletion`, `p` is a named object property; in `PredicateChange`, `p` and `q` can also be `rdfs:subClassOf`. `AnnotationAssertion(prop C value)` means an annotation whose subject is the IRI of `C`. `edge(C, p, P)` is shorthand for `SubClassOf(C ObjectSomeValuesFrom(p P))`; `edge(C, rdfs:subClassOf, P)` means `SubClassOf(C P)`.

| Change type | Removed evidence | Added evidence | Condition                                                                                                                      |
| --- | --- | --- |--------------------------------------------------------------------------------------------------------------------------------|
| `ClassCreation(C)` | — | `Declaration(Class(C))`, plus any added annotations on `C` and outgoing `SubClassOf(C X)` axioms | Atomic for the declaration alone; compound when other owned axioms are added. Requires `C` to be absent from the original class signature. |
| `NodeCreation(N)` | — | Added declaration(s) for non-class OWL entities with IRI `N`, plus added annotations on `N` | Atomic for one declaration alone; compound when multiple declarations or annotations are added. Requires `N` to be absent from the original signature. If a class is also newly declared with IRI `N`, annotations belong to `ClassCreation` instead. |
| `NodeDeletion(C)` | `Declaration(Class(C))`, plus any removed annotations on `C` and outgoing `SubClassOf(C X)` axioms | — | Compound. Requires `C` to be absent from the updated class signature.                                                          |
| `PlaceUnder(C, P)` | — | `SubClassOf(C P)` | Atomic.                                                                                                                        |
| `RemoveUnder(C, P)` | `SubClassOf(C P)` | — | Atomic.                                                                                                                        |
| `NodeMove(C, P, Q)` | `SubClassOf(C P)` | `SubClassOf(C Q)` | Compound; `P` and `Q` must differ.                                                                                             |
| `NodeRename(C, old, new)` | `AnnotationAssertion(rdfs:label C old)` | `AnnotationAssertion(rdfs:label C new)` | Compound. `C` must remain a class in both versions; labels must have the same language and datatype, with one unambiguous pairing. |
| `CommentChange(S, old, new)` | `AnnotationAssertion(rdfs:comment S old)` | `AnnotationAssertion(rdfs:comment S new)` | Compound. The IRI subject, language, and datatype must match; exactly one old and one new comment must be available for that pairing, and their text must differ. A class subject must not be newly created or deleted. |
| `CommentAddition(S, text)` | — | `AnnotationAssertion(rdfs:comment S text)` | Atomic. The subject is an IRI and the value is a literal. |
| `CommentRemoval(S, text)` | `AnnotationAssertion(rdfs:comment S text)` | — | Atomic. The subject is an IRI and the value is a literal. |
| `NewSynonym(S, p, text)` | — | `AnnotationAssertion(p S text)` | Atomic. `p` is one of the supported OBO synonym annotation properties; `S` is an IRI and `text` is a literal. |
| `RemoveSynonym(S, p, text)` | `AnnotationAssertion(p S text)` | — | Atomic; the reverse of `NewSynonym`. |
| `SynonymReplacement(S, p, old, new)` | `AnnotationAssertion(p S old)` | `AnnotationAssertion(p S new)` | Compound. The subject, synonym property, language, and datatype must match, with exactly one old and one new synonym to pair. A class subject must not be newly created or deleted. |
| `EquivalentClassesChange(C, old, new)` | `EquivalentClasses(C old)` | `EquivalentClasses(C new)` | Compound. Each axiom must have exactly two operands: the same named class `C` and one anonymous class expression. The old/new pairing must be unambiguous and the expressions must differ. |
| `EdgeCreation(C, p, P)` | — | `edge(C, p, P)` | Atomic. This is a class restriction, not an arbitrary RDF triple or creation of the property entity `p`.                       |
| `EdgeDeletion(C, p, P)` | `edge(C, p, P)` | — | Atomic; the reverse of `EdgeCreation`.                                                                                         |
| `PredicateChange(C, P, p, q)` | `edge(C, p, P)` | `edge(C, q, P)` | Compound; `p` and `q` must differ. Either side can instead use `rdfs:subClassOf` and its corresponding `SubClassOf(C P)` axiom. |
| `AddNodeToSubset(C, S)` | — | `AnnotationAssertion(oboInOwl:inSubset C S)` | Atomic; `C` and `S` are IRIs.                                                                                                  |
| `RemoveNodeFromSubset(C, S)` | `AnnotationAssertion(oboInOwl:inSubset C S)` | — | Atomic; the reverse of `AddNodeToSubset`.                                                                                      |

These are **candidate patterns**, not guaranteed final classifications. For example, removing `SubClassOf(C P)` and adding `SubClassOf(C Q)` produces a `NodeMove` candidate as well as separate `RemoveUnder` and `PlaceUnder` candidates. The search chooses a non-overlapping explanation by minimizing candidate cost. Among equal-cost explanations it minimizes `Σ -log(confidence)`, which is equivalent to maximizing the product of candidate confidences. A class creation/deletion candidate can also consume annotations and outgoing subclass axioms that otherwise would be separate changes.

The initial confidence policy assigns `1.0` to directly observed changes, `0.95` to unambiguous old/new pairings (`NodeRename`, `CommentChange`, and `EquivalentClassesChange`), `0.9` to structural inference (`NodeMove`), and `0.8` to weaker interpretations (`PredicateChange` and `SynonymReplacement`). When a child has several compatible move pairings, or an edge has several compatible predicate pairings, the relevant base confidence is divided by the number of compatible pairings. These values are heuristic ranking signals and must eventually be calibrated against manually labelled changes.

`ClassCreation` is the specific creation type for a named OWL class. `NodeCreation` covers a new IRI declared as another OWL entity type, such as an object property, data property, annotation property, datatype, or named individual. A newly declared class produces `ClassCreation`, not `NodeCreation` for the same class declaration. If several non-class entity types are declared at the same new IRI, they form one `NodeCreation` candidate.

Synonym candidates recognize `oboInOwl:hasExactSynonym`, `hasRelatedSynonym`, `hasBroadSynonym`, and `hasNarrowSynonym`. For example, replacing `"flu"@en` with `"influenza"@en` under `hasExactSynonym` offers `SynonymReplacement` (cost 1) and separate `RemoveSynonym` plus `NewSynonym` candidates (total cost 2). The search prefers replacement when the pairing is unambiguous. Different synonym properties or languages are not paired. The change records display literal values with their language or datatype suffix, while evidence retains the complete OWL axioms. A change only to annotations *on* a synonym axiom, with the synonym literal itself unchanged, remains an `AnnotationAddition`/`AnnotationRemoval` fallback.
